# 스프라이트 애니메이션

## 0. 시작 시
1. `animation_workflow_guide(use_case="character")`를 호출해 도구 사용 요령을 확인한다
2. 정지 스프라이트가 없으면 `pixel-sprite` 스킬로 먼저 **아래 방향(down) 1프레임**을 완성한다
3. 캔버스 크기를 확인한다: 지정이 없으면 32×32, 타일 수를 지정하면 `32×가로타일 × 32×세로타일` (CLAUDE.md 크기 규칙)
4. 요청에 마법·스킬 언급이 있는지 확인한다 (§1-1). 있으면 스킬마다 번호를 매겨 목록으로 정리한다
5. 만들 태그 목록, 프레임 수, 총 프레임 수를 표로 사용자에게 보고한다

## 1. 기본 세트 (캐릭터·몬스터는 항상 전부 생성)
**4개 동작 × 4방향 = 16태그 + `die` 1태그 = 17태그.** 사용자가 일부만 요청하거나 정지 이미지만 원한다고 명시한 경우에만 줄인다.

| 동작 | 프레임 | 프레임 시간(ms) | 루프 | 비고 |
|---|---|---|---|---|
| `idle` | 4 | 150~260 | 반복 | 호흡·출렁임. 32px 기준 1~2px만 움직인다 |
| `move` | 4~6 | 100~140 | 반복 | 접지 프레임을 길게. 좌우는 다리가 번갈아, 상하는 몸이 1px 오르내린다 |
| `attack` | 4~8 | 예비동작 150~200, 타격 70~90, 복귀 100~140 | 1회 | 예비 → 타격 → 복귀. 타격 프레임에 이펙트(휘두름 궤적)를 넣어도 된다 |
| `damage` | 3 | 70~110 | 1회 | 흰색(또는 밝은 색) 플래시 1프레임 + 공격 반대 방향 넉백 1~2px + 복귀 |
| `die` | 6~8 | 90~200, 마지막 프레임 400 이상 | 1회 | **방향 없이 1개.** 정면(down) 기준으로 쓰러짐·분해·소멸. 마지막 프레임은 잔해가 남거나 완전히 투명 |

**태그 이름**: `<동작>_<방향>`. 방향은 `down / up / left / right`이고 **생략하지 않는다**. 예외는 `die` 하나뿐이다.
```
idle_down   idle_up   idle_left   idle_right
move_down   move_up   move_left   move_right
attack_down attack_up attack_left attack_right
damage_down damage_up damage_left damage_right
die
```
- 타임라인 순서: 동작 순서(idle → move → attack → damage → die), 동작 안에서는 방향 순서(down → up → left → right). `die`는 맨 끝에 하나. 위 표 순서대로 한 파일에 이어 붙인다
- 1회 재생 태그(attack, damage, die)도 태그 direction은 `forward`로 두고, 게임 쪽에서 루프 여부를 정한다

## 1-1. 스킬 애니메이션 `skill_{N}` (마법·스킬이 언급된 경우에만)
캐릭터 요청에 **마법이나 스킬에 대한 별도 언급**이 있으면 기본 세트에 더해 스킬 애니메이션을 만든다. 언급이 없으면 만들지 않는다.
- 언급 예: "화염구를 쓰는 마법사", "돌진 스킬이 있는 기사", "힐과 보호막을 쓰는 사제", "독 브레스를 뿜는 드래곤"
- 언급으로 보지 않는 것: 직업·종족 이름만 있는 경우("마법사 그려줘"), 일반 공격("검으로 공격")은 `attack`으로 처리한다
- 직업만 있고 스킬이 모호하면 만들지 말고, 보고 표에 "스킬 애니메이션 추가 가능"이라고 한 줄 제안한다

**번호**: 언급된 순서대로 `skill_1`, `skill_2`, … 하나의 스킬은 하나의 번호를 갖는다. 같은 스킬을 다르게 표현한 것("화염구", "불덩이 날리기")은 하나로 친다.
**방향**: 다른 동작과 같이 4방향을 모두 만든다 → `skill_{N}_down / _up / _left / _right`

| 항목 | 규약 |
|---|---|
| 프레임 | 6~10 |
| 프레임 시간(ms) | 시전 준비 150~250, 발동 70~100, 여운·복귀 100~160 |
| 루프 | 1회 |
| 구성 | **준비(차징·자세) → 발동(최대 포즈 + 이펙트 피크) → 여운 → 복귀**. 마지막 프레임은 idle 첫 프레임 자세로 돌아온다 |
| 구분 | `attack`과 실루엣이 확실히 달라야 한다. 지팡이를 들어 올리기, 양손 모으기, 몸을 웅크렸다 펴기처럼 스킬마다 고유한 포즈를 둔다 |

**이펙트 레이어**
- 캐릭터 몸과 분리된 `fx` 레이어에 그린다. 몸 레이어는 다른 동작과 같은 팔레트와 외곽선 규칙을 지킨다
- 이펙트는 캔버스 안에 들어가는 범위만 그린다(손에 모이는 빛, 몸을 감싸는 오라, 발밑 마법진). **날아가는 투사체·광역 이펙트는 별도 스프라이트**로 따로 만들자고 사용자에게 제안한다. 캔버스를 키우지 않는다
- 이펙트 색은 스킬 속성을 따른다(불 = 주황·노랑, 얼음 = 하늘·흰색, 독 = 연두·보라, 신성 = 노랑·흰색). 이펙트 색은 캐릭터 팔레트와 별도로 3~4색 이내로 쓴다
- 방향마다 이펙트가 나오는 위치를 시전 방향에 맞춘다(down이면 몸 앞 아래, up이면 몸 뒤 위로 가려지게)

**태그 순서**: 기본 세트 다음, `die` 앞에 둔다.
```
idle_* → move_* → attack_* → damage_* → skill_1_* → skill_2_* … → die
```
스킬이 K개면 태그 수는 `17 + 4K`개다.

## 2. 방향 제작 규칙
- **down**(정면): 기준 포즈. 가장 먼저 완성한다
- **up**(뒷모습): 얼굴과 앞 디테일을 지우고 뒤통수, 등, 꼬리를 그린다. 실루엣과 발 위치는 down과 같게 유지한다
- **left**(옆모습): 측면 실루엣을 새로 그린다. 폭이 좁아지고 앞뒤 깊이가 드러난다
- **right**: left의 cel을 `flip_layer(horizontal)`로 뒤집어 만든다. 비대칭 디테일(무기 든 손, 눈가 흉터, 광원 하이라이트)은 뒤집은 뒤 수작업으로 고친다
  - **광원은 뒤집지 않는다**: 뒤집으면 하이라이트가 우상단으로 가므로 좌상단으로 다시 옮긴다
- 네 방향의 **발 위치(접지선)와 몸 중심은 같은 좌표**로 맞춘다. 방향을 바꿀 때 캐릭터가 튀면 안 된다
- 32px 1타일 캐릭터는 발끝을 캔버스 하단에서 1~2px 위에 둔다. 여러 타일 캐릭터는 발이 맨 아래 타일 행에 오게 한다

## 3. 절차
작업량이 크므로(17태그 + 스킬당 4태그, 약 80~100프레임 + 스킬당 24~40프레임) **방향 하나를 끝까지 완성한 뒤 다음 방향으로** 간다.

1. **down 방향 4개 동작(idle/move/attack/damage), 스킬(`skill_{N}_down`, 있을 때만), `die`**를 먼저 완성하고 검증한다 (아래 §4). 여기서 동작 디자인이 확정된다. `die`는 이후 방향 작업에서 다시 만들지 않는다
2. down 동작을 기준으로 **up → left** 순서로 만든다. 같은 동작은 프레임 수와 타이밍을 방향끼리 **똑같이** 맞춘다
3. **right**는 left 프레임 구간을 `duplicate_frame_range`로 복제하고 `flip_layer`로 뒤집은 뒤 §2 규칙대로 수정한다
4. 각 동작 안에서는:
   1. **키포즈**를 먼저 그린다(예: move는 접지·통과 2포즈). 프레임마다 새로 그리지 않는다
   2. `copy_frame` / `duplicate_frame_range` / `copy_cel`로 베이스를 복제한다
   3. 움직이지 않는 레이어는 `propagate_cels`로 해당 구간에 채운다
   4. 움직임은 `offset_cel_positions`, `tween_cel_positions_eased`로 **cel을 이동**해 만든다. 형태가 바뀌는 부분만 다시 그린다
   5. `set_frame_duration`으로 타이밍, `set_tag`로 구간을 지정한다
5. 스쿼시·스트레치는 부피를 유지한다(가로가 늘면 세로가 준다). 32px에서 1px은 약 3%이므로 과장하지 않는다
6. 프레임을 대량 복제하거나 뒤집을 때는 `run_lua_script` 한 번으로 처리해도 된다 (`pixel-sprite/references/lua-pitfalls.md` 참고)
7. 마지막에 태그가 모두 있는지(기본 17개 + 스킬 4K개) `get_sprite_info`로 확인하고, 태그·프레임 범위 표를 사용자에게 보고한다. 스킬이 있으면 번호와 스킬 이름의 대응표(`skill_1` = 화염구 …)도 함께 보고한다

## 4. 검증 (태그마다)
- [ ] `render_onion_skin(frame, Aseprite/preview/character/<name>/<name>_onion_f<N>.png, scale=8)`를 Read로 확인해 궤적이 매끄러운지 본다 (32×32 기준 8배 = 256px. 2×2타일 이상은 scale=4)
- [ ] 방향 4개의 같은 동작 첫 프레임을 나란히 보고 접지선과 몸 중심이 같은지 확인한다
- [ ] `compare_frames`: 인접 프레임 변화가 **0%면 중복 프레임**, 너무 크면 튄다
- [ ] `audit_animation` / `animation_sanitize(report_only=true)`: 레이어 누락과 범위 밖 cel 확인
- [ ] `export_tag(tag, Aseprite/preview/character/<name>/<name>_<tag>.gif, scale=6)`로 GIF를 만들고, 사용자에게 경로를 알려 재생 확인을 요청한다 (Claude는 GIF의 움직임을 볼 수 없다)
- [ ] 루프 태그는 마지막 → 첫 프레임 연결이 자연스러운지 `compare_frames(last, first)`로 확인

## 5. 하지 말 것
- 프레임마다 처음부터 다시 그리기 → 형태가 떨린다(boiling)
- idle에서 전신을 2px 이상 이동
- `die` 외 태그에서 방향 접미사 생략(`idle`만 쓰기, `skill_1`만 쓰기), `die`에 방향 붙이기(`die_down`), 옛 이름(`hit`, `dead`) 사용 → 게임 쪽 연동이 깨진다
- 스킬 이름을 태그에 쓰기(`fireball_down`) → 번호(`skill_1_down`)로 쓰고, 이름은 보고 대응표에만 적는다
- 마법·스킬 언급이 없는데 `skill_{N}`을 만들기, 스킬 이펙트를 몸 레이어에 섞어 그리기
- 방향마다 같은 동작의 프레임 수나 타이밍을 다르게 두기
- 모든 프레임에 같은 시간 → 기계적으로 보인다. 키포즈는 길게, 중간 프레임은 짧게

## 6. 마무리 (필수)
검수(`pixel-reviewer`) PASS 뒤 `game-export` 스킬로 게임용 결과물을 만들고 Unity 복사까지 확인해야 완료다.
1. `export_spritesheet` → `Aseprite/export/character/<name>/<name>_<W>x<H>t_sheet.png` + `_sheet.json` (`list_tags=true`)
2. `export_frame(1)` → `Aseprite/export/character/<name>/<name>_<W>x<H>t.png`
3. 태그별 GIF → `Aseprite/export/character/<name>/<name>_<W>x<H>t_gif/<tag>.gif`
4. 훅이 원본 `.aseprite`만 `Assets/Texture/character/<name>/`에 복사한다 (시트 PNG·JSON은 `Aseprite/export`에만 남는다). 파일이 생겼는지 확인하고 시트 크기·프레임 수·태그 수를 보고한다
